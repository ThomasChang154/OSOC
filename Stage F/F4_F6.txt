F4
-------------------
1. 代码执行到最后得到：
   {PC, r0, r1, r2, r3} = {7, 10, 10, 55, 1}
   显然，r0存储的是数列末项，r1存储的是每一步需要加上的数，r2存储的是加和结果，r3存储的是公差
2. 于是，为了计算1+3+5+7+9，只需在对寄存器初始化后，令r3为2即可：
   0: li r0, 9
   1: li r1, 0
   2: li r2, 0
   3: li r3, 1
   4: add r1, r1, r3
   5: add r2, r2, r1
   6: li r3, 2        # 修改公差
   7: bner0 r1, 4
   8: bner0 r3, 8
3. 程序执行到最后得到：
   {PC, sum, i} = {END, 55, 11}
   并输出 sum = 55
4. 根据状态机的思想，设时钟信号CLK、加数i、加至末项标志flag、加和结果sum，则：
   初态{0, 0, 0, 0} -> {1, 1, 0, 1} -> {2, 2, 0, 3} -> {3, 3, 0, 6} -> ... -> 
   末态{10, 10, 1, 55}
5. 对比汇编语言和C语言实现数列求和的代码，可知：
   编译器将C语言赋值语句编译成汇编语言中的装载li指令
         将C语言加法语句翻译成汇编语言中的加和add指令
         将C语言循环体中条件判断语句编译成汇编语言中的不等则跳转bner0指令

1. PC寄存器的位宽为32位；
   GPR共有31个（x[1]-x[31]），位宽均为32位；
   RV32I的R[0](x[0])，其所有位均被固定为0；sISA的R[0]，其所有位均可被更改；
   指令编码的位宽也是32位，指令有4种基本格式；
   需要5位表示一个GPR，因为GPR共有31个，至少需要用5位二进制数进行区分与表示；
   add指令的格式为：add rd, rs1, rs2  
                   # 0000000 rs2(5_bits) rs1(5_bits) 000 rd(5_bits) 0110011
   相比于RV32I，RV32E只有16个非特权寄存器（x[0]-x[15]），其他的细节与RV32I的均相同；
